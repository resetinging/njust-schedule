# 数据刷新策略

> 状态：现行
>
> 最后更新：2026-11-27

## 1. 目标

区分“用户个人数据”和“全校共享数据”的刷新责任：

- 用户主动刷新个人数据时，必须访问教务获取最新数据，不能只返回服务器快照。
- 共享数据只能由服务端获取和维护，小程序用户不直接访问教务或上游数据源。
- 个人数据不做夜间统一同步或登录后全量预抓；共享数据仍由服务端后台预热。

## 2. 个人数据

适用范围：

- 课表
- 考试安排
- 成绩与四六级
- 教学评价
- 校历
- 培养方案
- 学籍信息
- 一键刷新

规则：

1. 用户点击页面刷新按钮或在明确交互中提交刷新时，后端应实时访问教务。
2. 登录与普通页面进入只读取 MySQL 已有快照，不访问教务；缓存为空时显示空态，等待用户主动刷新。
3. 自动重登、Cookie 恢复和同请求合并可以保留，但不得把用户主动刷新改成“只读旧快照”。
4. `ALLOW_LIVE_REFRESH` 默认开启；仅运维排障时可临时设为 `0`，不得作为常规生产配置。
5. 合作商演示数据不访问教务，刷新返回“演示数据无需刷新”。

### 2.1 自动刷新例外

- 考试页进入时保留 30 分钟静默刷新时间窗，与手动刷新共享限制；后端按用户 3 次/分钟限流。
- 有订阅额度且提醒任务处于 active 的用户，继续运行考试/成绩提醒生命周期检测。
- 考试提醒：课程结课后立即检查考试安排；未找到或上游失败时与成绩提醒共用三阶段排期；找到未来考试后锁定到考试结束再停止。
- 成绩提醒：课程/考试结束后的第 1–7 天每天 `10:00 / 14:00 / 18:00` 检查；第 8–21 天每天 `06:00–23:00` 每小时检查；第 22–28 天恢复每天 `10:00 / 14:00 / 18:00`；第 29 天起不再检查。

## 3. 共享数据

### 3.1 空教室

- 用户请求只读取服务端缓存快照，不在请求线程访问教务。
- 缓存命中时立即返回。
- 缓存未命中时立即返回 `pending=true` 和“服务端正在准备数据”，由后台补缓存。
- 服务端启动时和每日 00:02 预热本周一至周日、两校区各大节的空教室数据。
- 小程序不得直接请求教务；不得把未命中误报为“该时段没有空闲教室”。

### 3.2 蹭课目录

- 用户查询只读取 MySQL 中的共享蹭课目录。
- 服务端每日 00:05 检查并刷新目录，管理员也可主动触发同步。
- 查询、候选目录和收藏不得在用户请求中访问教务。
- 目录刷新失败时保留上一份成功快照。

### 3.3 图书馆库存

- 小程序只请求本服务，不直接访问图书馆 OPAC。
- 本服务只访问匿名公共 OPAC，不携带用户 Cookie、Token 或 SSO 凭据。
- 图书馆数据不属于教务个人数据，不触发 JWC 请求。
- 检索和馆藏使用服务端共享缓存；上游失败可返回明确标记的旧缓存，不得伪造空结果。
- 由于检索关键词无限，图书馆不承诺全量午夜预取；缓存条目按既定 TTL 更新，客户端始终只连接本服务。

## 4. 禁止事项

- 禁止所有个人数据刷新接口默认返回“每日凌晨自动更新”并跳过教务。
- 禁止空教室用户请求同步等待教务查询。
- 禁止蹭课用户查询访问教务。
- 禁止小程序直接访问教务、OPAC 或携带教务 Cookie 的外部地址。
- 禁止把共享缓存失败返回成“0 条结果”或“没有空闲教室”。

## 5. 测试要求

- 个人数据：验证主动刷新会进入教务访问路径，而不是命中维护提示。
- 空教室：验证缓存命中直接返回；空缓存返回 `pending=true` 且不阻塞等待教务。
- 蹭课：验证查询路径只访问 store，不访问 JWC。
- 图书馆：验证请求不携带教务凭据，客户端 API 只指向本服务。
- 回归运行 `go test ./...`、`go vet ./...` 和小程序测试全集。
