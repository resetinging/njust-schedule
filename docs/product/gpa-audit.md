# GPA 计算审计报告（小程序 vs 第三方课表 APK vs 本地真实数据）

> 状态：研究记录；引用的数据和代码版本可能已变化

> 日期: 2026-09-01 · 数据: 本地库 9241xxxxxxxx 的 54 门真实成绩
> 背景: 用户反馈小程序 GPA 计算不准；已解析 base.apk（第三方课表 Flutter 应用）的 GPA 规则并与小程序实现逐条对比。

---

## 一、APK 解析结论（上一轮）

1. 每门课绩点来源：教务系统返回（`_decodeScores` 解析，本地仅等级制兜底）
2. 加权平均绩点：**GPA = Σ(课程绩点 × 课程学分) / Σ课程学分**（`_buildStats`/`_SemesterStats`）
3. 等级制映射（APK 字符串表证实，本地换算）：优 4.0 / 优- 3.7 / 良+ 3.3 / 良 3.0 / 良- 2.7 / 中+ 2.3 / 中 2.0 / 中- 1.5 / 及格 1.0
4. 平均分：百分制算术平均（等级制不参与）
5. 四六级：折算百分制（"｜折算 X"）→ 以 8 学分计入（保研口径）
6. 成绩选择：通识教育选修课默认不参与（`_shouldSelectScoreByDefault`；changelog：去除通用英语、重修成绩处理）

## 二、小程序实现（gpa.js / grades-view）

- `calcGpa`：Σ(绩点×学分)/Σ学分，`grade_point` 为 0/缺失时用 `scoreToGp(score)` 兜底；`gpaOnly` 排除通识教育选修课；缓考/缺考等（-1）不计入
- `scoreToGp`：等级表（同上）+ 百分制分段表 90→4.0 / 85→3.7 / 82→3.3 / 78→3.0 / 75→2.7 / 72→2.3 / 68→2.0 / 64→1.5 / 60→1.0 / <60→0
- `calcGpaBaoyan`：CET6>CET4 折算百分制替换英语模块 8 学分
- 平均分：仅百分制算术平均（`_numScore`）

## 四、用本地 54 门真实成绩实证（重要）

- 后端 `grade_point` 字段 **54 门全部为 0**（教务 getCjcx API 不返回绩点）→ 前端全部走本地换算，**单科绩点 = scoreToGp(成绩)** 是唯一口径

**三种口径计算结果：**

| 口径 | 参与课程 | Σ学分 | GPA |
|---|---|---|---|
| 小程序（排除通识教育选修课） | 46 门 | 96.7 | **2.92** |

## 五、用户"GPA 不准"的可能来源（按嫌疑排序）

1. **口径差异（最大嫌疑）**：小程序默认排除通识教育选修课（评奖/保研口径，与 APK 一致）；若用户对比的是教务处/学信网成绩单的"总 GPA"（学籍口径，可能含通识选修），数值会差约 **0.09**（2.92 vs 2.83）
2. **等级制 ± 变体绩点**：优-→3.7 等需与教务成绩单逐科核对（若教务按五级制 优=4.0 处理，则优- 取值不同）
3. **百分制分段表边界**：82/85/78 等边界分（与线性公式仅差 ±0.2/科，整体影响 <0.02）
4. **异常成绩**：'感官的化学密码' 成绩 0（疑似缺考/取消被记为 0）会按 0 绩点计入分母拉低 GPA；39/31 分同理
5. **平均分口径**：算术 79.33 vs 加权 78.95（若用户期望学分加权）

## 六、待用户核对清单（拿到即可精确定位）

1. 教务成绩单上**每门课的"绩点"列**：重点核对 优- / 良+ / 85 分 / 82 分 / 78 分 / 72 分 / 68 分 / 64 分 的绩点值
2. 教务成绩单/学信网显示的**总 GPA 数值**
3. 成绩单上通识教育选修课（尤其不及格/0 分那几门）是否显示绩点、是否计入总 GPA
4. 平均分：教务显示的是算术平均还是学分加权平均
