# 微信小程序上线流程

> 本文档是「南理工课表管理系统」微信小程序（仓库：`C:\Users\a\Documents\local\miniprogram`）
> 从开发到正式发布的完整操作指引。
>
> 配套后端仓库 `njust-schedule`（本仓库，部署于微信云托管）。

---

## 一、上线前置检查（每一项都必须满足）

### 1. 后端已部署最新版本 ✅ 必须在先

后端 `server` 分支最新提交已推送到 GitHub 后，在微信云托管控制台**重新构建部署**，
并确认：

```
GET https://<你的默认域名>/api/status
→ {"auto_login_attempted": false, "logged_in": false, ...}
```

- `auto_login_attempted: false` = 新版（仅手动登录）已生效
- 旧版（`auto_login_attempted: true`）会导致数据公开 + 自动登录，**禁止上线**

### 2. 小程序代码检查清单

| 检查项 | 位置 | 要求 |
|---|---|---|
| 联调开关关闭 | `utils/config.js` → `USE_LOCAL` | **必须为 `false`**（`true` 时线上请求 `127.0.0.1`，完全不可用） |
| 云环境 ID | `utils/config.js` → `CLOUD_ENV` | 与云托管控制台环境 ID 一致（当前 `prod-d1g32cv4n1430dfb6`） |
| 服务名 | `utils/config.js` → `CLOUD_SERVICE` | 与云托管服务名一致（当前 `flask-5da7`） |
| 服务名传递方式 | `utils/api.js` → callContainer | **必须用 `X-WX-SERVICE` header**（config 只放 env）；用 `config.service` 会导致网关 `INVALID_PATH` |
| AppID | `project.config.json` → `appid` | 正式 AppID（当前 `wx1d76c0631bdeebac`），不能用测试号 |
| 代码提交 | miniprogram 仓库 | 上线前将本地改动 commit 并推送（git）备份 |

### 3. 云环境绑定确认（callContainer 连通的前提）

`wx.cloud.callContainer` 要求云环境属于当前小程序 AppID：

1. 微信开发者工具 → 工具栏「云开发」图标 → 能打开控制台，且环境列表里有
   `prod-d1g32cv4n1430dfb6`
2. 小程序后台（mp.weixin.qq.com）→ 云托管 → 服务列表 → 服务 `flask-5da7` 存在且属于当前小程序
3. 开发者工具中登录的微信账号需是该小程序的管理员/开发者

## 二、本地联调（发布前全流程自测）

1. 微信开发者工具打开 `miniprogram/` 项目
2. 「详情 → 本地设置」：勾选「不校验合法域名」（仅本地调试需要，上传不受影响）
3. 编译运行，逐项验证：
   - 设置页：获取验证码（图片正常显示）→ 输入学号/密码/验证码 → 登录成功
   - 课表页：下拉刷新 → 显示课程
   - 考试页 / 成绩页 / 评教页：数据正常加载
4. 真机预览（点「预览」扫码）：同一套流程在手机上再测一遍

> 常见问题：
> - 报 `INVALID_PATH` → 检查 `api.js` 是否用 `X-WX-SERVICE` header 传服务名
> - 报 `env not found` → 云环境未绑定当前小程序（见「一、3」）
> - 数据接口 401 → 后端未登录，先去设置页手动登录
> - 登录成功后仍拿不到数据 → 后端是否已部署新版；容器是否刚重启（会话丢失需重登）

---

## 三、隐私合规（提审前必须完成）

小程序收集了「学号、密码」等个人信息，**必须**在公众平台声明：

1. 小程序后台 → 设置 → 服务内容声明 → **用户隐私保护指引**
2. 声明收集的信息：账号（学号）、密码
3. 用途说明示例：
   > 学号与密码仅用于登录用户本人的教务系统以获取课表、考试、成绩等信息，
   > 仅提交至用户本人部署的服务器，不用于任何其他用途，不在本地留存密码。
4. 勾选对应隐私接口（若使用 `wx.getPrivacySetting` 等需一并声明）

---

## 四、上传代码

1. 微信开发者工具 → 工具栏「上传」按钮
2. 填写：
   - 版本号：`1.0.0`（后续递增）
   - 项目备注：本次改动摘要（如「首次发布」）
3. 上传成功后在公众平台可见

---

## 五、提交审核

1. 小程序后台 → 管理 → 版本管理 → 开发版本 → 「提交审核」
2. 填写审核信息：
   - 功能页面：勾选 课表 / 考试 / 成绩 / 评教 / 设置 / 校历
   - **测试说明（关键）**：
     > 本小程序为个人学习工具，需使用用户本人教务账号（学号/密码/验证码）登录后使用，
     > 审核人员如无账号将无法体验核心功能。已附功能截图与使用说明。
   - 建议附上功能截图（课表页、成绩页、登录页）
3. 提交后等待审核（通常 1~7 天）

> 常见被拒原因与对策：
> - 「核心功能无法体验」→ 测试说明里写清楚需本人账号，附截图/录屏
> - 「未声明隐私信息收集」→ 完成「三、隐私合规」
> - 「类目不符」→ 确认类目为「工具 → 效率」等通用工具类目

---

## 六、发布

1. 审核通过 → 版本管理 → 审核通过的版本 → 「全量发布」
   （也可先「分阶段发布」给少量用户验证，稳定后再全量）
2. 发布后真机验证一次正式版

---

## 七、日常维护须知

| 事项 | 说明 |
|---|---|
| 后端重新部署 | 部署后容器重启 → 所有用户教务会话丢失 → 需重新登录 |
| 后端代码更新 | 修改后 push `server` 分支 → 云托管控制台重新构建部署 |
| 小程序代码更新 | 开发者工具「上传」新版本 → 公众平台提审 → 发布 |
| 多用户 | 每位用户独立登录(token 会话)、数据按学号隔离互不可见 |
