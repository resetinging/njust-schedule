## 一、性能优化：Cookie 本地恢复不再重复全量预抓

### 目标

避免 24 小时内使用 Cookie 本地恢复时再次执行约 14 次教务全量预抓。

当前基线：

- 本地恢复登录本身约 4 次教务 HTTP。
- 登录成功后仍会执行约 14 次后台预抓。
- 实际第二轮登录总访问量约 18 次。

目标：

- 已有完整缓存且未超过 30 天：本地恢复不再全量预抓。
- 缺失数据：补齐缺失数据。
- 无法判断完整性：执行一次完整预抓。
- Cookie 失效并回退真实 SSO：执行完整预抓。
- 用户主动刷新：始终强制访问教务。

### 实现方案

1. 增加用户级完整缓存元数据。
   - 使用 `settings` 键：`{student_id}:data_cache_at`。
   - 完整预抓成功后写入当前时间。
   - 缓存有效期沿用 30 天数据缓存周期。
   - 用户清除缓存数据时同步删除该元数据。

2. 登录流程区分真实登录和本地恢复。
   - `sso`：完整预抓。
   - `sso-cached`：
     - 元数据有效且数据完整：跳过预抓，返回 `skipped=true`。
     - 元数据缺失或数据不完整：补齐数据。
   - 本地 Cookie 失效后回退 SSO：完整预抓并刷新元数据。

3. 后台同步状态。
   - 跳过预抓时直接发布 `done` 状态。
   - 增加 `skipped=true`，前端停止轮询。
   - 会话失效中止、失败和部分成功的状态语义保持现有规则。

4. `/api/status` 短时缓存。
   - 按当前用户会话缓存约 2～3 秒。
   - 减少多个组件同时请求导致的重复数据库查询。
   - 登录、退出、设置修改、手动刷新后主动失效。

5. 批量写库。
   - 课表和成绩预抓改用 SQLAlchemy 批量插入。
   - 保留按用户、按学期“先删后写”语义。
   - 批量写入失败时回退现有逐条写入。

### 验收

- 首次真实 SSO：完整预抓。
- `sso-cached` 且缓存有效：不再全量预抓。
- `sso-cached` 且缺少元数据：自动补齐。
- Cookie 失效回退 SSO：完整预抓。
- 用户主动刷新：不受缓存元数据限制。
- 清除数据：元数据同步清理。
- 旧前端兼容、退出保留密码、24 小时信任规则不受影响。

## 二、空教室 Cookie 来源重构

### 目标

空教室抓取不再长期依赖单一服务账号，改为从已有本科教务会话中随机选择，同时保留服务账号兜底。

### 候选优先级

1. 活跃本科会话池。
   - 从 `_sessions` 中筛选：
     - `account_type == "undergraduate"`
     - `logged_in == True`
     - 学号非空
     - 未超过 `SESSION_TTL`
   - 使用 `secrets.choice` 随机选择。
   - 同一轮刷新复用同一会话。

2. 持久化本科 Cookie。
   - 来源：`settings` 中的 `{student_id}:jwc_session`。
   - `session_store` 新增 `account_type` 字段。
   - 旧数据没有账号类型时，按现有规则回退判断：
     - 学号以 `1` 开头视为研究生。
     - 其他视为本科。
   - 单次最多读取和解密有限数量的候选。
   - 临时 `JWCClient` 只加载 Cookie，不调用密码登录。

3. 服务账号。
   - 保留当前 `_classroom_service_client`。
   - 支持持久化会话复用。
   - 失效时按现有逻辑重新登录。
   - 所有用户 Cookie 都不可用时作为最终兜底。

### 失效与重试

- 第一个候选返回登录页或明确会话失效时，标记失效并尝试下一个候选。
- 网络错误和登录失效要区分：
  - 登录失效：淘汰候选。
  - 网络异常：切换候选，但不直接删除持久 Cookie。
- 候选重试上限默认 5 个。
- 所有来源失败时保留旧缓存，不返回错误的“0 间空闲”。

### 并发与安全

- 活跃用户会话使用现有 `_jwc_request` 实例锁和全局并发限制。
- 持久化临时客户端同样遵守全局教务并发限制。
- 同一用户已有活跃会话时优先复用活跃会话，不重复创建临时客户端。
- 不读取用户课表、成绩、评教或个人资料，只调用教室借用查询。
- 日志只记录来源类型、脱敏学号和失败原因，不记录 Cookie 值。
- 不向小程序返回 Cookie，不延长用户 token 有效期。

### 配置

- `FREE_CLASSROOM_COOKIE_SOURCE=auto`
  - 活跃会话 → 持久化 Cookie → 服务账号。
- 可选调试值：
  - `active-only`
  - `persistent-only`
  - `service-only`
- `FREE_CLASSROOM_CANDIDATE_RETRIES=5`
- `FREE_CLASSROOM_PERSISTED_LIMIT=50`

### 验收

- 只选择本科会话，不选择研究生会话。
- 多候选时可随机选择，且整轮刷新复用同一 Cookie。
- 首个 Cookie 失效时自动切换下一个。
- 活跃池为空时使用持久化 Cookie。
- 持久化 Cookie 不可用时回退服务账号。
- 服务账号失败时保留旧缓存。
- 用户自身请求与空教室抓取并发时不串 Cookie。
- 不记录 Cookie 和密码。

## 三、蹭课查询功能

### 前置判断

当前系统没有全校课程目录：

- 个人课表只包含当前用户自己的课程。
- 培养方案只包含当前用户专业计划。
- 不能通过枚举其他学生课表实现全校查询。

必须先把“全校开课查询”作为新的教务数据源。

### 第一阶段：教务页面勘察

编码前必须完成：

1. 使用真实本科账号定位全校课程查询、开课查询或课程信息查询页面。
2. 解析页面表单 action、字段名、提交编码、分页方式。
3. 确认返回字段：
   - 学期
   - 课程代码、课程名称
   - 教学班号
   - 教师
   - 开课单位
   - 学分
   - 课程属性
   - 周次
   - 星期、节次
   - 校区、教学楼、教室
4. 确认是否包含全部本科教学班，是否可跨学期查询。
5. 如果教务没有全校目录接口，需要重新定义功能，不能绕过隐私边界。

### 第二阶段：后端目录

新增全局课程目录表：

- `course_catalog_sections`
  - `semester`
  - `course_code`
  - `course_name`
  - `section_code`
  - `teacher`
  - `department`
  - `campus`
  - `credits`
  - `course_type`
  - `exam_type`
  - `updated_at`
- `course_catalog_meetings`
  - `section_id`
  - `weekday`
  - `start_period`
  - `end_period`
  - `weeks`
  - `building`
  - `room`

建议索引：

- `semester + course_name`
- `semester + teacher`
- `semester + department`
- `semester + weekday + start_period`

同步流程：

1. 后台使用本科 Cookie 候选池或服务账号访问课程查询页。
2. 分页抓取并解析。
3. 按 `semester + course_code + section_code` 去重。
4. 全量事务替换当前学期数据。
5. 同步失败时保留旧目录。
6. 用户搜索只查数据库，不直接访问教务。

### 第三阶段：API

- `GET /api/audit-courses`
  - 查询参数：`q`、`semester`、`teacher`、`department`、
    `campus`、`weekday`、`jc1`、`jc2`、`page`、`limit`
- `GET /api/audit-courses/<id>`
  - 课程详情和所有上课时段。
- `GET /api/audit-courses/meta`
  - 可选学期、院系、校区、同步时间和课程数量。
- `POST /api/admin/refresh-course-catalog`
  - 管理端或后台任务手动刷新。

### 第四阶段：小程序

- 在“校园工具”或“课业”中增加“蹭课查询”入口。
- 搜索栏 + 院系/教师/校区/星期/节次筛选。
- 结果卡片展示：
  - 课程名
  - 教师
  - 上课时间
  - 周次
  - 教室
  - 学分和课程属性
  - 与本人课表的冲突状态
- 结果详情使用底部弹层。
- 支持加载、空结果、错误、目录未同步状态。
- 默认分页 20 条，避免一次性渲染过多数据。

### 后续增强

- 收藏/旁听计划。
- 仅显示与本人空闲时间不冲突的课程。
- 按教学楼、课程性质、是否考试筛选。
- 将旁听课程加入本地自定义课表。

### 隐私边界

- 只使用教务官方全校课程目录。
- 不展示其他学生名单、成绩或个人数据。
- 不使用其他学生课表接口枚举课程。
- 同步 Cookie 不写日志、不返回前端。
- 更新隐私指引，说明公共课程目录的数据来源和用途。

### 验收

- 能完整分页抓取当前学期本科课程目录。
- 课程名、教师、时间、周次、教室等字段解析正确。
- 用户搜索不访问教务，仅查询数据库。
- 目录同步失败时旧数据仍可搜索。
- 支持关键词、教师、院系、校区、星期、节次筛选。
- 能标记与用户自己的课表冲突。
- 旧前端和现有功能不受影响。
