## Bug #3 [已修复] WebVPN 教务登录 POST 到错误的端点

- **文件**: `jwc_client.py` → `_login_jw_through_webvpn()`
- **严重程度**: 🔴 核心 bug
- **现象**: 提交登录表单到 `Verifyservlet`（HTML 页面 form action），
  结果显示"用户名或密码错误"。
- **根本原因**: NJUST 直连登录使用 `POST /Logon.do?method=logon`（8080 服务器），
  然后服务器返回 302 → `9080/LoginToXk?method=jwxt&secret=...`。
  `Verifyservlet` 可能只是前端验证或旧端点，不是实际登录处理入口。
- **修复**: 完全重写 `_login_jw_through_webvpn()`，流程镜像直连登录：
  1. GET `{JW_BASE_8080_VPN}/Logon.do?method=logon` — 获取登录页
  2. GET `{JW_BASE_8080_VPN}/Logon.do?method=logon&flag=sess` — 会话初始化
  3. GET 验证码图片（`verifycode.servlet`）→ OCR
  4. POST `{JW_BASE_8080_VPN}/Logon.do?method=logon` — 提交登录
  5. 跟随 302 重定向到 `9080/LoginToXk`
- **副产品修复**: 
  - 验证码重试循环现在每次加 `&t=<timestamp>` 避免缓存，真正获取新验证码
  - 更详细的日志（OCR 结果长度、重定向链、失败原因）

## Bug #5 [⚠️ 今日引入，需回滚] WebVPN 前缀配置错误

- **文件**: `config.py`
- **严重程度**: 🔴🔴 破坏性回归 — 导致所有数据访问失败
- **引入**: 今天分析 `debug_jw_login_result.html` 时，错误地将重定向页面的
  WebVPN 前缀当作 9080 服务器的永久前缀。

### 详细分析

**原始配置（昨天，正确的）**:
```python
WEBVPN_PREFIX_9080 = "77726476706e69737468656265737421f2fc4b8b693e62456d1cc7a99c406d361c"
JW_BASE_9080_VPN = f"{WEBVPN_BASE}/http/{WEBVPN_PREFIX_9080}{JW_PATH_PREFIX}"
```
此前缀 `f2fc...` 用于所有教务访问（登录和数据）。登录页加载成功、
正常跳转都用的这个前缀。

**今天错误的修改**:
```python
# 把上面这个改名为 "8080 前缀"（因为 debug 页面中 port_data=""）
WEBVPN_PREFIX_8080 = "77726476706e69737468656265737421f2fc4b8b693e62456d1cc7a99c406d361c"
# 从 debug_jw_login_result.html 提取了新前缀（port_data="9080"）
WEBVPN_PREFIX_9080 = "77726476706e69737468656265737421a2a713d27661311e2659c7fdc906"
```

**为什么新前缀是错的**:
新前缀 `a2a7...` 是从登录 POST 响应页（"用户名或密码错误"页面）提取的。
这是 WebVPN 重定向过程中生成的**临时/会话级前缀**，不是教务服务器的永久前缀。
WebVPN 用它解码得到的目标地址是 `202.119.81.113:80`（不存在），
导致所有数据请求返回：
```
错误代码：CONNECTION_FAILED
Get http://202.119.81.113/njlgdx/...: dial tcp ... ->202.119.81.113:80: connect: no route to host
```

**证据**（debug 文件均为 03:27 生成，内容一致）:
- `debug_schedule_main.html`: 无法访问 `http://202.119.81.113/njlgdx/framework/main.jsp`
- `debug_schedule_page.html`: 同上
- `debug_exams_no_table.html`: 无法访问 `http://202.119.81.113/njlgdx/xsks/xsksap_list`
- `debug_eval_page.html`: 无法访问 `http://202.119.81.113/njlgdx/xspj/xspj_find.do`
- `debug_grades_step1_query.html`: 无法访问 `http://202.119.81.113/njlgdx/kscj/cjcx_query`
- `debug_grades_GET列表页.html`: 无法访问 `http://202.119.81.113/njlgdx/kscj/cjcx_list`

所有目标地址都是 `202.119.81.113:80`（端口 80，而教务在 8080/9080）。

### 回滚方案

```python
# config.py 应该恢复为：
WEBVPN_PREFIX_9080 = "77726476706e69737468656265737421f2fc4b8b693e62456d1cc7a99c406d361c"
# 不需要单独的 WEBVPN_PREFIX_8080，同一个前缀可以路由到不同端口
# JW_BASE_9080_VPN 恢复原来的写法
JW_BASE_9080_VPN = f"{WEBVPN_BASE}/http/{WEBVPN_PREFIX_9080}{JW_PATH_PREFIX}"
```

**关键认知修正**: WebVPN 前缀 `f2fc...` 由网瑞达系统静态生成，映射到教务系统的
内部 IP。前缀本身编码了目标，`port_data` 只是 JS 辅助变量，不代表实际端口。
同一个前缀跨会话持久有效（不是 session-specific）。

### 需要同步修改 `jwc_client.py`:
- import 恢复为只使用 `WEBVPN_PREFIX_9080`（不区分 8080/9080）
- `JW_BASE_8080_VPN` 也使用这个前缀
- `_resolve_url` 恢复原来的替换逻辑

## 技术备忘

### NJUST 教务双服务器架构
- **8080**: 登录认证（`202.119.81.113:8080`）— `Logon.do`、`Verifyservlet`、`verifycode.servlet`
- **9080**: 业务数据（`202.119.81.112:9080`）— `LoginToXk`、课表/成绩/考试/评教
- 登录流程: `POST 8080/Logon.do` → 302 → `9080/LoginToXk?method=jwxt&secret=XXX`

### WebVPN (网瑞达) 前缀
- 前缀 `77726476706e69737468656265737421f2fc...` 由 WebVPN 静态编码
- 通过 `/http/{prefix}/` 路径代理（如 `/http/{prefix}/njlgdx/...`）
- 也支持 `/http-9080/{prefix}/` 格式（端口后缀），但这是运行时生成的
- **前缀跨会话持久，不应从重定向页面提取**

### ddddocr 验证码识别
- 教务验证码 4 位数字/字母，位于 `verifycode.servlet`
- OCR 重试需要每次重新 GET（加时间戳避免缓存）

### SSO 密码加密
- `_encrypt_sso_password(password, salt)`: AES-128-CBC
- 随机 64 字符前缀 + 随机 16 字节 IV + PKCS7 填充 + base64 输出
