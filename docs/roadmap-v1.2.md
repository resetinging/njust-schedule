# v1.2.0 版本规划

> 目标：社区化（留言/反馈）+ 交互优化（周次/布局）+ 新工具（空教室）
> 原则：不破坏现有功能；每个功能可独立灰度；数据层统一走"按用户隔离 + 缓存"既有模式

---

## 一、留言板功能（P0，社区化第一步）

### 需求
- 登录用户可在小程序发布留言（文字），查看全部留言
- 管理员可在控制面板查看/删除留言（不当内容治理）

### 技术方案
| 层 | 方案 |
|---|---|
| 数据 | 新表 `board_messages`（id, student_id, student_name, content, created_at）；container.config.json executeSQLs 补充建表 + 存量库 `create_all` 兜底 |
| 后端 | `GET /api/board`（分页取最近 200 条，30s 缓存）+ `POST /api/board`（需登录，内容 ≤200 字，基础敏感词过滤，**每用户 10 秒限 1 条**防刷） |
| 控制面板 | 「留言」Tab：列表（学号/姓名/内容/时间）+ 删除按钮（`DELETE /api/admin/board/<id>`） |
| 小程序 | 「我的」页新增入口 → 独立页面 `pages/board/board`：留言列表（下拉加载更多）+ 输入框发布；未登录提示登录 |

### 工作量 / 风险
- 后端 ~1 天，前端 ~1 天；风险低（独立功能，不动现有模块）
- 注意：留言内容用户生成内容（UGC），需基础过滤 + 管理员删除能力

## 二、优化周次切换（P0，交互）

### 需求
- 当前 ◀▶ 按钮 + picker 跳转在 20 周时操作繁琐
- 目标：快速跳任意周，同时保留现有入口

### 方案（渐进增强，不动现有按钮）
- **周次快速选择条**：工具栏下方新增横向滚动胶囊条（1-20 周，当前周高亮），点选即跳转
  - 实现：`scroll-view scroll-x` + 20 个胶囊，复用 `filterByWeek`
  - 当前周（actualWeek）加"本"角标，双周模式（单/双周课）正常过滤
- 保留 ◀▶ 与 picker（下拉选周）——三个入口并存，用户习惯不被破坏

### 工作量
- 前端 0.5 天，零后端改动；风险极低

## 三、空教室查询（P1，需先调研数据源）

### 需求
- 按 周次+星期+节次 查询空闲教室

### ⚠️ 关键前提：数据源调研（必须先做）
| 数据源 | 可行性 |
|---|---|
| 强智教务"空教室/教室课表"接口 | **需实测**：强智部分版本有 `kbcx/kcbxxs` 教室课表查询，若可用则按教室抓取占用表 |
| 教务处公开课表 | 部分学院官网公开课表（爬取成本高、覆盖不全） |
| 自建教室基础数据 | 无教室占用数据源则不可行 |

### 方案（假设教务接口可用）
- 后端：抓取各教学楼教室课表 → 按（周/天/节）建占用索引 → `GET /api/free-classrooms?week=&day=&period=` 返回空闲教室
- 数据缓存：占用表 24h 缓存 + 手动刷新（教务数据变动低频）
- 前端：「工具」入口 → 空教室查询页（周/天/节选择器 + 教学楼筛选 + 结果列表）
- 风险：**教务接口不存在/变动 → 本项目降级为 P2 或取消**（先花 1-2 天验证接口，出结论再排期）

### 工作量
- 数据源可用：后端 2-3 天 + 前端 1 天；数据源不可用：**砍掉或换方案**

## 四、优化界面布局（P1，体验走查）

### 范围
1. **骨架屏**（v1.1 遗留）：课表/考试/成绩加载时用骨架占位替代"加载中…"文字，减少跳动
2. **布局统一走查**：卡片间距/圆角/字体层级统一（基于现有紫色主题变量化：抽出 `--card-radius`/`--card-shadow` 等设计变量）
3. **空状态优化**：各页空态图标+引导文案统一（含"去登录/去刷新"操作按钮）
4. **暗色模式**：**评估后决定**（涉及全部页面配色，工作量大，倾向 v1.3）

### 工作量
- 骨架屏 1 天、布局统一 1 天、空状态 0.5 天；风险低（纯样式）

## 五、问题反馈渠道（P1，社区化配套）

### 需求
- 小程序内提交问题反馈（类型：功能建议/Bug/其他 + 描述 + 可选联系方式）
- 管理员在控制面板查看/标记处理状态

### 技术方案
- 复用留言板基础设施：新表 `feedback`（id, student_id, type, content, contact, status, created_at）
- 后端：`POST /api/feedback`（需登录，内容 ≤500 字，10 秒限 1 条）+ `GET /api/admin/feedback`（分页/状态筛选）+ 状态更新接口
- 前端：「我的」页 → 「意见反馈」入口 → 表单页（类型选择 + 文本域 + 联系方式）+ 提交成功提示
- 控制面板：「反馈」Tab：列表（状态标签/类型/内容/时间）+ 标记处理/忽略

### 工作量
- 后端 0.5-1 天（复用留言板模式）、前端 0.5 天；风险低

## 版本节奏建议

| 阶段 | 内容 | 预估 |
|---|---|---|
| 1 | 空教室**数据源调研**（出结论：做/砍）+ 周次快速选择条 | 2-3 天 |
| 2 | 留言板（后端+小程序+控制面板） | 2 天 |
| 3 | 反馈渠道 + 骨架屏 + 布局统一 | 2-3 天 |
| 4 | 空教室（若数据源可行）+ 回归测试（34+29 全绿）+ 真机验证 | 3-5 天 |

## 风险与保障

- **空教室数据源是最大不确定项**：阶段 1 必须先调研，不可行则砍（避免烂尾）
- 留言/反馈为 UGC：限流 + 内容长度限制 + 管理员删除，控制面板治理
- 每个功能独立提交、独立测试；回归测试保持全绿再合并
- 周次优化为纯前端增量，风险最低，可最先上线
